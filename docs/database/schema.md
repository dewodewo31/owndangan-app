# Database Schema

## Naming Conventions

- Tables: `snake_case` plural (e.g., `users`, `events`, `guestbook_messages`)
- Columns: `snake_case`
- Primary keys: `id` (UUID)
- Foreign keys: `{table}_id` (e.g., `user_id`, `event_id`)
- Timestamps: `created_at`, `updated_at`, `deleted_at`
- Soft delete: `deleted_at` (nullable timestamp)
- Status columns: use `status` varchar, not boolean

## Entity Relationship Summary

```
users
  ├── subscriptions (1:N)
  ├── transactions (1:N)
  ├── events (1:N)
  ├── guests (1:N, via events)
  ├── rsvps (1:N, via guests)
  └── guestbook_messages (1:N, via events)

events
  ├── event_sections (1:1)
  ├── guests (1:N)
  ├── rsvps (1:N, via guests)
  ├── guestbook_messages (1:N)
  ├── photos (1:N)
  └── music (1:1 or 1:N)

packages
  └── subscriptions (1:N)

guests
  └── rsvps (1:1)

templates
  └── events (N:1 or optional)

transactions
  └── subscriptions (1:1)
```

## Soft Deletes

Tables with `deleted_at`:
- users
- subscriptions
- events
- guests

Tables with hard deletes (no deleted_at):
- transactions (kept for audit)
- guestbook_messages (kept for moderation)
- audit_logs (immutable)
- analytics_events (immutable)
- rsvps (immutable snapshot)
- gallery_photos
- music

## GORM Notes

- Composite unique indexes with soft delete: use unique index with WHERE deleted_at IS NULL.
- JSONB columns in GORM: `datatypes.JSON` or custom type.
- UUID type in GORM: use `uuid.UUID` with `gorm.UUID` or custom type.
- Timestamps: GORM auto-manages `CreatedAt`, `UpdatedAt`, `DeletedAt` if named correctly.
