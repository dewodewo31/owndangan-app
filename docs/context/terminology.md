# Terminology

## Roles & Users

| Term | Definition |
|------|------------|
| User / Pengantin | Platform user who creates and manages wedding invitations |
| Admin | Platform owner/operator who manages users, packages, templates, and monitors the platform |
| Guest / Tamu | Invitee who views the public invitation and optionally RSVPs or sends messages |

## Core Entities

| Term | Definition |
|------|------------|
| Event / Undangan | The wedding invitation entity containing couple info, event dates, and all invitation content |
| Subscription | A user's paid access to a package tier with specific features and limits |
| Package | A pricing tier (Free, Basic, Premium, Pro) defining feature limits and price |
| Transaction | A payment record for a package purchase via Midtrans |
| Guest | A person invited to the wedding, managed by the couple |
| RSVP | A guest's attendance response (yes/no/maybe) |
| Guestbook / Buku Tamu | Messages sent by guests displayed on the invitation |
| Digital Gift / Amplop Digital | Bank accounts, e-wallet, or QRIS info displayed for digital gift giving |

## Invitation Statuses

| Status | Definition |
|--------|------------|
| Draft | Invitation being created, not yet publicly accessible |
| Published | Invitation is publicly accessible via `/[slug]` |
| Unpublished | Invitation was published but is now hidden (returns 404) |

## Subscription Statuses

| Status | Definition |
|--------|------------|
| Active | Subscription is valid and premium features are enabled |
| Expired | Subscription period has ended, features revert to Free tier |
| Pending | Payment received but subscription not yet activated (intermediate state) |
| Cancelled | Subscription terminated by admin |

## Transaction Statuses

| Status | Definition |
|--------|------------|
| Pending | Payment initiated but not completed |
| Settlement | Payment successfully completed (Midtrans authoritative) |
| Expire | Payment window expired |
| Deny | Payment denied by bank/processor |
| Cancel | Payment cancelled by user |
| Refund | Payment refunded |

## Technical Terms

| Term | Definition |
|------|------------|
| Slug | URL-friendly unique identifier for an invitation (e.g., `andi-sinta`) |
| Snap Token | One-time token from Midtrans to open Snap payment popup |
| Webhook | HTTP POST notification from Midtrans to backend on payment status change |
| JWT | JSON Web Token for authentication |
| GORM | Go ORM library for database operations |
| Feature Flag / Capability | JSONB-based entitlement flags stored in packages |
| Soft Delete | Database deletion marked by `deleted_at` timestamp instead of row removal |
| Entity | Core business object represented as a database table |
| Handler | HTTP request handler in Go backend |
| Service | Business logic layer in Go backend |
| Repository | Database access layer in Go backend |

## Platform Areas

| Term | Definition |
|------|------------|
| User Dashboard | `/user/*` — Couple's invitation management interface |
| Admin Dashboard | `/admin/*` — Platform operator's management interface |
| Public Area | `/*` (non-dashboard) — Landing page, pricing, `/[slug]` invitation |
| Editor | The invitation content editor (9 sections) within user dashboard |
| Billing | Package purchase and transaction history within user dashboard |

## Payment Terms

| Term | Definition |
|------|------------|
| Midtrans Snap | Hosted payment page supporting all Indonesian payment methods |
| Server Key | Midtrans secret key for backend API calls |
| Client Key | Midtrans public key for frontend Snap.js initialization |
| Order ID | Unique transaction identifier generated by the platform |
| Gross Amount | Total transaction amount in IDR |

## Package Tiers

| Term | Definition |
|------|------------|
| Free | Default tier with limited features (7 days, 100 guests) |
| Starter | Entry paid tier (30 days, Rp 99K) |
| Premium | Mid-tier (60 days, Rp 299K) |
| All Access | Top tier (lifetime, unlimited, Rp 999K) |
